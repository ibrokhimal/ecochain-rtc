# RTC verification against 172.20.10.3

## Environment

Server accessed through SSH as user01, working directory ecochain-rtc/server. Local client address 172.20.10.14. Tests used separate rooms prefixed codex-. Existing source edits were present before this run.

## Results

- Remote health endpoint returned ok. TCP signaling and UDP media sockets were listening.
- Local Rust suite passed 38 tests: 21 unit, 3 media, 4 resilience and 10 signaling.
- Flutter analyze passed for SDK, shared UI and both apps. All 19 unit/widget tests passed.
- Freshly rebuilt local loadtest against the remote server, 2 participants, one remote video per participant, 10 seconds: audio delivery min 75.6%, average 76.2%; video delivery min 68.4%, average 80.4%. A second room measured audio average 80.1%, video average 70.4%.
- Remote loopback loadtest, 2 participants, 8 seconds: audio delivery average 87.4%; video average 95.5%. These ratios use synthetic media and nominal frame rates, not perceptual quality measurements or direct network packet-loss percentages.
- An earlier pre-existing local loadtest binary reported zero media; after rebuilding from current source, media arrived. The initial zero result is not a reliable measurement of the current source.
- macOS integration runner built and exited successfully, but its output contained signaling socket closed and SDP m-line order errors. It did not expose the test's FREEZE/RESUMED/AUDIO BYTES markers, so this run does not independently substantiate the intended audio-after-resume assertion.
- At the final snapshot there were zero active participants and zero signaling connections. Empty rooms may remain until their TTL expires.

## Open findings

Remote src/room/media.rs SHA-256 was aedf288fe0204df4cf69173bed0cbf0d7350be9ca8d869589b808c3467bd02fc. Local SHA-256 was 010796d23c6b99fabf0e8129a05feb5daebfc040a65e0e79a0cb3fec99b9694b. Local uncommitted edits change pending-offer retry behavior specifically related to SDP m-line ordering. The running remote build cannot be assumed to include those edits.

Audio/video delivery ratios were below the expected nominal rates even in remote loopback. Further instrumentation is needed to distinguish generator behavior, SFU drops and network effects. Server UDP dropped counter rose from 153 to 5471 over the overall run; that counter includes server routing/queue drops and does not identify radio packet loss.

No remote code deployment or server restart was performed. No physical phone, microphone audibility, screen-sharing or full two-Flutter-app visual verification was completed in this run.
